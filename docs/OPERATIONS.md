# LeagueDesk 操作手册

## 初始化与岗位

首次使用管理员登录。“账号”中新建裁判和参赛负责人，选择其组织与默认角色，设置独立强密码后以安全方式告知本人；不可公开共享密码。一个报名单位由一个负责人账号报名，团队显示名不表示实现队内球员管理。

“角色”支持权限和数据范围：管理员 ALL；主办人员 DEPARTMENT；裁判 ASSIGNED；报名负责人 PARTICIPANT。参赛角色只允许 `events` 和 `register`；裁判排赛需要具有 `referee` 的启用账号。菜单隐藏不替代后端鉴权；账号或组织停用立即限制 API。最后一个启用的完整管理员不能停用或降权。

## 建立赛事与报名

1. 在“赛季与场地”中建立同组织的启用赛季和场地。
2. 新建赛事草稿，选择赛季、分类、赛制、名额、胜局制与开始／结束时间。小组赛每组至少两人、最多16人，不少于预设晋级人数。开放后规则冻结。
3. 开放报名。参赛负责人到赛事页登录报名，或主办人员为已建立账号登记；公开显示名需要确认同意，备注仅本人和工作人员可见。
4. 主办方在“报名”页审核并设置不重复种子序，再逐条签到。审核再次修改会清除签到，需要重新确认。未签到或未审核者不进入签表。
5. 生成签表之前核对实际到场名单与赛制。生成后不再接受新报名，不支持临时替补／换人。仅开放报名阶段可撤回和重新报名；历史不删除。

## 排赛与录分

赛程表筛选场地、参赛单位、阶段或状态。在已确定双方的比赛点击“排赛”，选择同组织启用场地、裁判、起止时间。时间按浏览器时区，保存 UTC；不得超出赛事时段或超过4小时。场地、裁判、负责人跨赛事时间重叠会被拒绝；相邻时段可以排。下游双方未确定不能提前排赛。

裁判登录“裁判工作台”，进入本人指定赛事，在计划前30分钟以内或之后开赛。未指派本人不能开赛或录分。开赛时再次核对场地、人员及冲突。填入双方胜局数，胜方恰好达到所需局数、败方低于所需局数；弃权选择胜方，双方记录0:0，不冒充实际比赛局分。

全部小组比赛结束后，主办方生成淘汰赛。小组排名依胜场、净胜局、胜局数、种子序；并非所有协会的正式规则。淘汰赛自动推进胜方与轮空，后续场次确定后需单独排赛。全部淘汰赛结束才可完成赛事；完成后产生赛季积分。

## 更正与取消

比分更正只能由主办方执行，必须注明理由并保留旧／新结果。小组更正仅允许晋级前；淘汰更正仅允许所有下游尚未开赛，改变胜方会清空受影响下游排赛，必须重新安排。已完成赛事冻结。若比赛正在进行，先提交比赛结果才能取消赛事；取消保留报名、已完成结果与历史，不代表退款或撤销实际发生事项。

## 公开页面与导出

开放后可发布或取消发布。复制赛事“公开页面”链接，公众无需登录即可查看显示名、赛程、排名和签表。公开页面每15秒更新，可切换大屏显示，取消发布后接口返回不可用。工作人员私有备注、负责人账号和审计不会出现在公众数据里。报名显示名和赛事说明是公开信息，不填写真实隐私资料。

有导出权限的人员可下载当前赛事比赛 CSV，不含账号密码或私有报名备注；公式前缀做转义。赛季积分仅在管理员／主办统计页，冠军5、亚军3、其他实际入签者1；与官方运动评级没有关联。

## 常见异常

- 版本冲突：刷新核对最新状态后重新填写，不强制覆盖他人操作。
- 网络中断提示结果未知：先刷新看实际记录，不直接重复提交。服务端命令支持幂等，但前端不会盲目重放未知写入。
- 无法生成小组：核对审核、签到、重复种子、每组人数与晋级参数。
- 无法排赛：核对启用的同组织场地和裁判、时间范围以及跨赛事双方负责人占用。
- 无法更正：下游已开始或赛事已完成，不能直接改数据库绕过历史约束。
- 登录失效：重新登录；管理员密码环境变量只初始化空库，不会在重启时重置已有密码。

后端6项编排／输入单元测试验证2–16人循环赛每对仅一次、同轮不重复、2–64人淘汰种子与轮空、蛇形分组、相邻时段和CSV公式转义。19项Spring集成测试使用真实Security、Flyway、JPA及H2 MySQL兼容模式，覆盖：

- 五人循环赛到决赛和积分；五人直接淘汰的轮空与完赛。
- 审核／签到／重复种子；报名重复、公开名同意与撤回再报。
- 场地、裁判、参赛负责人冲突分别拒绝，相邻时间允许；数据库时间微秒精度统一。
- 不合法比分不结束比赛；进行中无法取消；更正清空未开赛下游排赛，下游开赛／小组晋级后更正拒绝。
- 匿名隐私、取消公开、参赛越权、裁判越权、CSRF、停用现有账号会话、最后管理员和命令重放／版本冲突。

前端9项测试覆盖真实CSRF头、授权CSV下载、失效会话、权限拒绝、超时未知结果与写入不自动重放。格式检查使用Spotless/Prettier，前端lint使用ESLint。镜像构建包含测试，不允许跳过。

独立MySQL8.4验收 `scripts/quality.py` 通过HTTP创建TEST资料，覆盖五人循环→晋级→完赛，五人轮空淘汰含弃权，双组循环晋级，以及进行中／开放报名赛事；验证权限、公开字段、取消发布、排赛冲突、同时重放及积分。断言数记录在本机 output/mysql-quality.json，测试状态／业务快照保持私有，不提交。脚本拒绝非本机和非空赛事库。

重启之后 `scripts/verify-persistence.py` 比对五场赛事完整详情、报名、比赛、操作历史和赛季积分。备份恢复到另一个全新项目后运行同一核对；迁移必须实际建表且再次启动不重复初始化。恢复脚本校验备份格式与校验和，并拒绝已有目标资源、占用或无效端口。已有实例、已占用的 Docker 发布端口、损坏校验和三项拒绝行为已实际验证；验证在创建新目标资源前执行。

发布检查包括README链接与图片存在、原始二维码哈希一致、LOGO、公司、双语联系与非商业授权、自有源码署名、敏感变量与源文件审查，详见release-check.py。真实浏览器另检验登录、角色、主办与参赛／裁判页面、公开签表、中英文、移动宽度、取消公开及无OS弹窗截图。

这些测试不证明官方运动规程适配、生产负载、外网渗透或所有浏览器兼容性；未实现功能见README。重新验收使用独立空库，不改客户或现有业务数据。
